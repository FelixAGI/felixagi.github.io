    The complete derivation

    From one address to the exact byte.

    FelixQR describes a deterministic byte space. Every read follows the same equations, whether the volume is four kilobytes or spans the verified 298 address example.

    1. 01

      Pack the description

      The QR carries a compact FX1 envelope. FXB1 contains the file tree, geometry, VM program, metadata, and any literal bytes needed for exact recovery.

      FX1 | base64url(FXB1) | crc32(FXB1) Description size: D = |FXB1| bytes. Stored description information: 8D bits.
    2. 02

      Build the recursive lattice

      Each axis contributes independently to the address space. More axes or states extend the space without changing the addressing rule.

      N = q · ∏j=0d-1 nj Nsample = 4 · 1624 = 298 byte addresses q is the channel count, d is the dimension count, and nj is the number of states on axis j. FX1 does not impose a fixed d.
    3. 03

      Translate address into coordinates

      Mixed-radix division turns one linear byte address into a channel and a coordinate on every axis. The inverse equation returns the same address.

      c = A mod q,   p = ⌊A / q⌋ xj = p mod nj,   p = ⌊p / nj⌋,   j = d - 1 ... 0 A = q · (...((x0n1 + x1)n2 + x2)...) + c Alattice(y) = start + y Aorbit(y) = start + ⌊y / b⌋ · stride + (y mod b)
    4. 04

      Express state as rotation

      A state can be represented as an angular translation. Two 16-state rotations carry the high and low nibbles of one byte.

      θ(s, r) = 2πs / r b = (shigh << 4) | slow,   s ∈ [0, 15] The moving-line carrier observes the state; the decoded FX1 checksum rejects a wrong observation.
    5. 05

      Compile files into a 2D grid

      The current web compiler divides each file into 256-byte cells. Cells are laid out row-major and become coordinates in the geometry VM.

      cell(y) = ⌊y / 256⌋,   within(y) = y mod 256 z = row · columns + column The address is now a place in the lattice, not a requirement to materialize every preceding byte.
    6. 06

      Fit each cell locally

      Each cell selects the shortest exact explanation available: a constant, repeating period, line, curve, XOR ramp, translated orbit, or literal bytes.

      Mconstant(r) = k Mrepeat(r) = P[r mod |P|] Mlinear(r) = (a + sr) mod 256 Mquadratic(r) = (a + br + cr2) mod 256 Mxor(r) = a XOR ((sr) mod 256) Morbit(r) = (P[r mod k] + ⌊r/k⌋d) mod 256
    7. 07

      Intertwine matching branches

      Cells with the same model and the same sparse corrections share one VM branch. The lattice selects that branch wherever the pattern reappears.

      g(i) = g(j) iff modeli = modelj and Δi = Δj F(y) = Δ(y), if present; otherwise Mg(cell(y))(within(y)) The correction map stores the requested replacement byte, so the result remains byte-for-byte exact.
    8. 08

      Select the smallest exact encoding

      The compiler measures the complete binary, not just the pattern. It keeps geometry only when geometry beats the literal representation.

      E* = arg min |FXB1(E)| E ∈ { literal, global model, cell lattice } subject to decode(E)[y] = source[y] for every y
    9. 09

      Place it in an ordinary QR

      The final camera link must fit the selected QR version and error-correction level. Small descriptions travel directly; larger exact sources use a short locator.

      |cameraURL(FX1)| ≤ QRcapacity(version, ECC) FQX1 = (repeat, name, |B|, B),   filet = B |logical files| = repeat · |B|,   H(filet) = H(B) logical bytes = generated bytes + stored literals The verified image set stores the original 70,277-byte JPEG once and exposes 1,000 byte-identical files through a version-4 QR link.

    From camera to files

    Four steps. No mystery.

    Your camera handles the QR. FelixFS turns what it reads into a usable drive.

    1. Scan

      Use the camera app already on your phone. It reads FelixQR as a normal QR code.

    2. Check

      FelixFS verifies the volume before opening it, so a damaged code is caught immediately.

    3. Generate

      The geometry recreates exactly the bytes needed for the file and position you requested.

    4. Browse

      The result appears as a read-only drive on your phone or computer.
